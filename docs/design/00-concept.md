# gikai.niho.life 構想 v0.4

作成 2026-10-31（paneB-8）。v0.2 は owner の追加依頼（資料の図書館・スタンス表明・市民発の提案・街のこれから）と調査 06〜08 を反映。v0.3 は owner の判断（同日）で「市民から市への提案」をやめ、**市民も市も議員もパートナーとして案を磨く「フォーラム（熟議の場）」**に改めた。v0.4 でフォーラムの最初の形を **GitHub Discussions のような軽い投稿とコメント** に絞り、案の比較・段階・磨き上がりの条件は応用機能（後の段階）へ下げた。画面の説明文も極力なくす。owner と一緒に揉むための草案。根拠は `docs/research/01〜05`。確定した判断は末尾の「決めること」を「確定（owner 日付）」に書き換えて残す。

## 1. 一言でいうと

**「鎌倉で いま決まりつつあることを、暮らしの言葉で、経緯ごと。ひとこと返せる。」**

- 目的は 2 つ。街の政治を **わかる** ようにする。街の政治に **関わりやすく** する。
- NIHO の「まちを知る」の一部。運営は NIHO（政党・候補者と関係のない、街のリビング）。
- 対象は鎌倉市民。最初の公開は市民が「見る」だけで価値がある形にし、「関わる」は段階的に足す。

## 4. 設計原則

1. **テーマが主語。** 会議・議案・発言・予算はテーマにぶら下がる。時系列で経緯を見せる（N1・N5）。
2. **暮らしの言葉で。ただし必ず原文へ。** 要約は AI が下書きし、人が確かめてから出す。会議録・録画・PDF への出典リンクを必ず置く。AI 生成の範囲を明示する（N9・先行事例 8）。
3. **「今」が軸。** 会期中は今回の議会、会期外は次の議会と最近決まったこと。次に起きること（締切・日程）を先に知らせる（N8）。
4. **関わる入口は軽く、出口を見せる。** 賛否＋ひとことから始め、集計がどこへ届き、どんな反応があったかを記録する（N6・N7。先行事例 4・10）。
5. **党派色なし。** 賛否は事実だけ。評価の言葉を使わない。選挙期間中の扱いを決めておく（N9）。
6. **既存を複製しない。** 会議録検索・録画・Liqlid・「わたしの提案」・パブコメにはリンクで接続する（先行事例 11）。
7. **自動化できないと続かない。** 会議録と予算 PDF の取り込みを先に作り、人の作業は「確認」と「見出しを書く」に絞る（spending.jp の教訓）。
8. **NIHO の強みは場。** 画面だけで完結させず、リビングでの「議会を読む会」と往復させる。議会報告会の参加者は「イベント会場」を 72% が望んでいる。
9. **聞く前に返事の約束。** 誰が・いつまでに・どの形で返すかを先に示す。返事は 3 段階（受付・途中経過・結末 = 反映／一部／見送り＋理由）。見送りも「回答なし」も同じ台帳に載せる（調査 08・Decide Madrid の失敗）。
10. **軽い反応を終点にしない。** スタンプを押した直後に、日付つきの次の一歩（読む会・パブコメ・ひとこと）を出す。読むだけでも参加として数える（調査 08）。
11. **一方向にしない。** 市民が市に要望する窓口ではなく、市民・市・議員が同じ輪で案を磨く。市からの相談も同じ形で出す。「返事が来た件数」「読んだ人数」のような数字は置かない（owner 2026-10-31）。
12. **要望でなく案を磨く。** 設備や人員を増やす要望は自然に多くなる。だから磨く条件に「費用・財源・担い手・困る人」を入れ、費用は予算データで文脈づけ（例: 警備員 2 人 = 年 400 万円 = 観光費の 1%）、選ぶのは「いちばん受け入れられる案」（同意型）。磨けた案の出口は「市がやる・一緒にやる・自分たちでやる・議会へ」の 4 つで、市に頼むだけにしない（owner 2026-10-31・ソシオクラシー・調査 07）。
13. **二択で割らない。** 全件には「共感した／なるほど／うーん」、重要議題には「賛成／反対／まだ決められない＋理由」、対立の深い争点には同意型（異議なし／懸念あり／異議＋代案）を使い分ける（調査 07・ソシオクラシー）。

### 作らないもの

- 自由なスレッド型の掲示板（加古川で討論 0・世田谷で噛み合わず）。
- 議員の発言数ランキングなど量の順位（TheyWorkForYou が撤去）。
- 市のサービスの複製（Liqlid・会議録検索・録画・パブコメ）。
- NIHO としての賛否・論評。
- 候補者を選ぶ投票、議員との「一致度」（公職選挙法 138 条の 3・杉並区の中止例）。
- 「署名」という名前の機能（138 条の 2。賛同と呼ぶ）。

## 6. 画面と URL の骨格

スマホを主、PC で深掘り。URL は人が読める形にする。画面の説明文は置かず、文字より絵（顔スタンプ・アイコン）。アプリのヘッダー（ロゴ＋名前）はホームだけに出し、他の画面は見出しと戻るだけ（owner 2026-10-31）。

| URL | 画面 |
|---|---|
| `/` | 会期中は「今回の議会」、会期外は「次の議会」と「最近決まったこと」。テーマ一覧。予算の入口。 |
| `/topics/<slug>` | テーマ。**初めての人が分かる順**: 写真と一行 → 「3 行で」 → 「どんな問題？」（平易な 2〜3 段落＋写真 2 枚）→ 意見が分かれるところ → これまで（時系列）→ よくある質問 → みんなの意見（要約＋理由）→ 資料室・フォーラム・予算・議員 → 最後に顔スタンプ（owner 2026-10-31。みらい議会の「ポイント→理由→分かれるところ→FAQ」と国会図書館 Issue Brief の「要点 3 行→概要→論点」に沿う） |
| `/sessions/2026-12` | 定例会。5 つのトピック、日程、議案と結果、陳情 |
| `/budget/2026` | 予算の俯瞰 → `/budget/2026/<款>` → `/budget/2026/p/<事業>` |
| `/members/<id>` | 議員 |
| `/calendar` | 次に起きること |
| `/forum`, `/forum/<id>`, `/forum/new` | フォーラム（投稿とコメント）。投稿は右下の＋ |
| `/me` | マイページ（通知・フォロー・自分の投稿・ニックネーム・ログアウト）。右上のアバターから |
| `/about` | 運営・中立の約束・AI の扱い・データの出どころ・訂正の窓口 |

## 7. データの流れ

```
会議録（kensakusystem.jp）──取得──▶ 発言ブロック ──LLM──▶ テーマ付け・要約・経緯 ──人が確認──▶ 公開
予算書 PDF（市）──既存パイプライン（全 14 款へ拡張）──▶ JSON ──▶ 可視化
議案・陳情・日程（市ページ）──構造化──▶ 一覧・カレンダー
```

- 会議録の二次利用条件・録画の埋め込み可否は未確認。早い段階で市議会事務局に挨拶し、CSV・API の提供を相談する。
- データモデルは最初から「市」を単位に持つ（鎌倉以外を入れられる形）。画面は鎌倉専用。

## 8. 信頼と中立の運用

- AI 要約には「AI が下書き・NIHO が確認・原文はこちら」を常に表示。
- 賛否・採決は市の公表と会議録の記載だけを載せる。推定は書かない。
- 訂正の窓口を置き、訂正履歴を公開する。
- 選挙期間中は候補者になる議員のページを凍結し、新しい評価を載せない（公職選挙法への配慮。細部は専門家に確認）。
- ひとことは NIHO アカウント必須・ニックネーム表示・返信なし・通報あり。個人への攻撃と個人情報は非表示にする。
- 公職選挙法: 選挙期間中は候補者名と賛否を結ぶ表示を止める。18 歳未満は議題への意見はできるが候補者の応援はできない。個人名つきの賛否は既定で出さず、出すなら明示同意（「信条」は要配慮個人情報）。
- 陳情は住所氏名が公開されるので、陳情化の前に提案者へ説明する。賛同数を陳情に添えられるかは議会事務局に確認する。

## 10. 決めること（owner へ。推奨つき）

**確定（owner 2026-10-31）: D1〜D9 はすべて推奨のとおり。** 同日のモック v2 への判断: コインの絵は撤去、提案の赤は弱める、「今週○人が読んだ」「提案に返事が来た」の数字は置かない、市民→市の一方向の提案はやめてフォーラム（熟議）にする、市からの相談も出せるようにする。フォーラムは GitHub のフォーラムのように簡単に投稿してコメントで議論できれば十分で、案の比較は応用機能。「3 つの案。11/20 の熟議の会で話す」のような要約的な行や「市民 38・市 観光課…」のような内訳は不要。画面の説明文（「鎌倉で動いている論点。写真を押すと…」など）はできるだけ減らしてシンプル・直感的に。 あわせて「できるだけ親しみやすい UI/UX で、シンプル・スタイリッシュ・直感的に」が画面づくりの基準。

| # | 論点 | 推奨 |
|---|---|---|
| D1 | ドメインと名前 | ドメインは `gikai.niho.life`。画面の名前は「鎌倉の議会」のような固い名詞句。 |
| D2 | 段階 1 の対象 | 本会議と予算等審査特別委員会。常任委員会は段階 2。 |
| D3 | ひとことの形式と時期 | Pol.is 型（賛否＋100 字・返信なし）。段階 2 から。NIHO アカウント必須・ニックネーム表示。 |

| D5 | 議員別の賛否 | 公表と会議録にある範囲だけ。足りない分は議員に直接確認して掲載する運用を段階 2 で試す。 |
